# dsh-mymemory

DeepSeek Harness 的长期记忆插件。数据只有一个 SQLite 文件加两个 Markdown 文件，都在你自己的盘上，没有云、没有遥测、没有运行时依赖。

写它的起因很具体：我用过的记忆方案都有同一个毛病——每一轮都往系统提示词开头塞一段新总结。前缀一变，缓存作废，省下的那点 token 还不够赔的。所以这里反着做：注入的东西小、位置固定、字节有硬上限。

## 装

```bash
git clone https://github.com/diyun7e7q/dsh-mymemory.git
npm install link:/absolute/path/to/dsh-mymemory
```

插件通过 `cordis.patch.yml` 注册，重启宿主后出现在插件列表里。需要 Node >= 24.9（直接跑 TS 源码靠 type stripping），以及一个提供 `llm` 服务的宿主。

## 它记住什么

两类东西分开存，因为它们被改的频率完全不同。

事实进 SQLite：身份、偏好、约束、项目，每条带来源、版本历史、墓碑。你会手动改的那两份文本进 Markdown：`SOUL.md` 是它怎么说话，`USER.md` 是它认为你是谁。改文件立即生效，不用重启，不用重建索引。

## 什么能进常驻块

这是最要紧的一条，也是我和别的记忆方案分歧最大的地方。

常驻块是每轮对话都会原样带上的那段内容，硬上限 1200 字节（UTF-8 字节，不是 token）。现在库里 27 条记录，其中 12 条进常驻块，占 1170 字节。

只有三类有资格：身份、偏好、约束。而且内容得是「下个对话仍然成立」的陈述。带路径、日期、任务态词（正在、下一步、2026-11-16 这类）的句子会被判成项目进度，自动降级成 project——内容一个字不改，只是不带进对话。模型很爱把「正在改注入段」存成身份，不拦的话每个对话都会带着一句昨天就过期的话。

项目态、经验、事件一律不进常驻块，需要的时候走检索。

## 什么时候才算数

模型抽到的东西不会立刻生效，先落 `pending`，对常驻块不可见。转正只有两条路：

你亲口说的（「记住 X」）当场算数。同一条事实在另一个对话里再次出现——包括措辞变了但说的是同一件事——就算坐实。

同一个会话里重复不算，那只是一段话被抽了两遍，不是两次独立观察。

七天没有被复现的 `pending` 会自动删掉，连索引一起清。所以这套东西里没有「待确认队列」需要你去点，确认交给了时间和重复次数。

有一条路我试过又否掉了：把「跟原话逐字相同」放宽成「实词覆盖八成」。袋装词分不出「我喜欢苹果」和「我喜欢香蕉」，覆盖率一样，放宽就是拿记错换记多。宁可漏。

## 前缀缓存

注入走 `ctx.systemPrompt.section({name, order, text})`，段名和 order（80 / 85）运行期恒定，所以注入块在前缀里的位置恒定；预算是字节硬截，库里记的事再多也涨不上去。

唯一能让前缀失效的事件是画像正文真的变了，而这个被刻意限流：最快 60 秒一次，一天最多 20 次，模型还被要求「信息没有实质变化就不要返回」。正常干一天活是零到几次失效，不是每轮一次。

这只是关于本插件自己那几个字节的说法。端到端的命中率还要看服务商的 TTL、淘汰策略和客户端改写，我不替它们承诺。

## 写入前的三道闸

精确哈希 → 近重复签名（90% 阈值）→ 模型仲裁，按 project / global 分桶。精确重复返回原记录而不是复制一份，语义重复合并来源，真冲突进收件箱等人裁决。

每条记录都留来源、版本和墓碑。遗忘前先落快照，可以回滚。

## 面板

右侧抽屉，两屏：概括和设定。

概括就是 `USER.md` 那段文字——直接点进去改，失焦保存；下面一行是常驻块的实测占用（12 件事 · 1170 / 1200 字节），这个数是现算的，不是估算。设定是 `SOUL.md`，末尾一个折叠的引擎账本，默认收着。

「重新整理」只生成提案，点「采用」才写盘。你手改过的措辞不会被模型静默盖掉。

界面是深空底加玻璃卡片，自己画的。react 由宿主注入，这个 bundle 没有构建步骤，所以样式全是内联对象，也没有外部 CSS、字体或图标库。

终端里照样能用：

```
/mymemory status
/mymemory conflicts
/mymemory skills
/mymemory skill <id> promote
```

## 配置

`cordis.patch.yml` 是活配置，不是模板：宿主按它链接插件，改这个文件等于改一个正在运行的插件。要挪库，写指针文件更稳——它的优先级高于 `config.dataDir`，而且不进版本控制。

```json
// <host home>/mymemory/<profile>/location.json
{ "dataDir": "/path/to/memory" }
```

把 `config.dataDir` 注释掉又没写指针，是搞出一个静默空库的标准方式。

面板里只放改了有意义、而且用户改得动的几个字段；其余参数留在配置里，写进界面只会制造假的自由度。

| 参数 | 默认 | 范围 | 含义 |
|---|---|---|---|
| `coreBudget` | 1200 | 0–2048 | 常驻块预算，UTF-8 字节 |
| `retrievalBudget` | 512 | 0–8192 | 检索结果注入预算，字节 |
| `maxResults` | 8 | 1–20 | 单次检索返回条数 |
| `maxMemoryChars` | 2000 | 16–2000 | 单条记忆字符上限 |
| `pendingTtlDays` | 7 | 1–365 | 待确认记录多久没人提就过期 |
| `nearDupPercent` | 90 | 50–100 | 第二道闸的相似度阈值 |
| `dailyLimit` | 20 | 0–1000 | 每天抽取调用上限 |
| `minIntervalMs` | 60000 | — | 两次画像重写的最小间隔 |

## 隐私

事实、版本、墓碑、冲突都在这一个 SQLite 文件里，权限 `0700`，无同步、无遥测、无账号。

跟模型对话时，被注入的那部分会离开本机到达模型服务商。本地存储不等于离线推理。

遗忘会清掉正文、版本和派生对象；它不动宿主的会话历史，也不动服务商的日志。

## 自己量一下

```bash
node scripts/benchmark.mjs
```

自带的是离线合成基准，5 个用例，只覆盖检索和 token 打包。它自己在输出里写得很清楚：`offline_synthetic_retrieval_only`，不能证明真实任务成功率，也不能证明比别的插件省。

## 开发

```bash
npm run typecheck   # tsc --noEmit
npm run build       # src/ → lib/
npm test            # 128 个测试
```

`lib/` 从 `src/` 生成，不要手改。无头管理界面在 `node lib/cli.js help`。

## 局限

只支持 DeepSeek Harness，不做跨宿主同步。依赖宿主提供 `llm` 和会话路由；两样都没有时回落到显式配置的路由，并且把这件事说出来，而不是假装成功。不索引完整对话，只存抽出来的点和观察。抽取质量受模型限制，规则是宁可漏：没来源不记，一次性不记，推测不记。
